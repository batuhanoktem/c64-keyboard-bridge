# Bridge protocol v1

TCP is a byte stream. Receivers handle partial headers, partial payloads, and several frames in one read. Every normal bridge message has this eight-byte header:

| Offset | Size | Meaning |
| --- | --- | --- |
| 0 | 2 | ASCII `KB` (`4B 42`). |
| 2 | 1 | Version `1`. |
| 3 | 1 | Message type, `1..8`. |
| 4 | 2 | Payload length, unsigned little-endian, at most 64. |
| 6 | 2 | Sequence number, unsigned little-endian. |

The maximum frame size is 72 bytes. Each direction independently starts at sequence zero and increments once per frame, wrapping from 65535 to zero. A gap, duplicate, unsupported version, malformed payload, or oversized frame ends the session; decoders do not resynchronize by searching for magic bytes.

| Type | Message | Direction | Payload |
| --- | --- | --- | --- |
| 1 | HELLO | C64 → host | Token 16 bytes; capabilities LE16; ID length 1 byte; printable ASCII device ID, 1–32 bytes. |
| 2 | HELLO_ACK | Host → C64 | Input enabled, exactly one byte `0` or `1`. |
| 3 | KEY_DOWN | C64 → host | Physical key ID; modifier mask, exactly two bytes. |
| 4 | KEY_UP | C64 → host | Physical key ID; modifier mask, exactly two bytes. |
| 5 | STATE_SYNC | C64 → host | Eight-byte matrix. |
| 6 | HEARTBEAT | Either | C64 sends matrix, eight bytes; host sends enabled flag, one byte `0` or `1`. |
| 7 | ERROR | Either | Error code; optional printable ASCII text, up to 63 bytes. |
| 8 | DISCONNECT | Either | One-byte reason. |

Capability bit `0x0001` denotes matrix keyboard state, and `0x0002` the separate network probe. The deployed C64 patch block has room for a device ID of at most 19 bytes, although the wire decoder permits 32. Tokens and arbitrary binary data must never be handled as NUL-terminated strings.

Normal initialization is HELLO, HELLO_ACK, then STATE_SYNC. The host validates peer address and token before admitting state. A new session establishes a baseline: an ordinary key already held cannot type until it has been released. Any later STATE_SYNC must agree with the host's ordered transition state. An agreeing snapshot can refresh held-key quarantine without changing the user's enabled/paused intent; a disagreement ends the session and releases bridge-owned output. Reconnect establishes a fresh baseline.

## Physical matrix and modifiers

The matrix consists of eight bytes in CIA1 PA selector order. Bit `1` means pressed after normalizing the CIA's active-low input. A key ID is `PA selector × 8 + PB bit`, with `0..63` valid. The modifier mask is aggregate Shift=`1`, Control=`2`, Commodore=`4`; all other bits are invalid. Each key event carries the mask *after* that transition. The host rejects duplicate transitions and masks inconsistent with its physical state.

| PA selector | PB0 | PB1 | PB2 | PB3 | PB4 | PB5 | PB6 | PB7 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 0, IDs 0–7 | Delete | Return | CursorRight | F7 | F1 | F3 | F5 | CursorDown |
| 1, IDs 8–15 | Num3 | W | A | Num4 | Z | S | E | LeftShift |
| 2, IDs 16–23 | Num5 | R | D | Num6 | C | F | T | X |
| 3, IDs 24–31 | Num7 | Y | G | Num8 | B | H | U | V |
| 4, IDs 32–39 | Num9 | I | J | Num0 | M | K | O | N |
| 5, IDs 40–47 | Plus | P | L | Minus | Period | Colon | At | Comma |
| 6, IDs 48–55 | Pound | Asterisk | Semicolon | Home | RightShift | Equal | UpArrow | Slash |
| 7, IDs 56–63 | Num1 | LeftArrow | Control | Num2 | Space | Commodore | Q | RunStop |

SHIFT LOCK appears as held LeftShift, ID 15; it has no separate ID. RESTORE is not a matrix key. Modifier presses precede ordinary presses and ordinary releases precede modifier releases when a complete scan changes several keys.

Both peers send a heartbeat about once per second and expire a silent session after three seconds. Both a C64 heartbeat and any mid-session STATE_SYNC must agree with the host's ordered transition state. A disagreement ends the session; STATE_SYNC cannot replace conflicting state within that connection. For example, a C64 ambiguity suspension that clears local accepted state may require disconnect and reconnect before a fresh baseline can be admitted. No character text or host layout interpretation is performed in the C64 wire layer. Repeat is generated by the host/backend, rather than transmitted as repeated physical downs.

## Probe exchange and observation record

The networking probe uses a HELLO with probe capability and HELLO_ACK, followed by raw bytes rather than additional v1 keyboard frames. The C64 sends the fixed 32-byte test payload, the host replies `ACK` plus NUL, and the C64 sends `READ_OK\n`. After recognizing idle read, it sends `IDLE_OK\n` followed immediately by this fixed 97-byte record:

| Offset | Size | Meaning |
| --- | --- | --- |
| 0 | 2 | ASCII `PB`. |
| 2 | 1 | Observation format version `1`. |
| 3 | 1 | Presence bitmap; all five rows present is `0x1F`. |
| 4 | 5 | ASCII build version, currently `0.1.0`. |
| 9 | 1 | Network Target identity byte length, at most 22. |
| 10 | 22 | Identity prefix, zero-padded. |
| 32 | 65 | Five 13-byte transaction rows. |

Rows are Identify, Open, binary Write, ACK Read, and idle Read, in that order. Within each row: operation byte at offset 0; first eight status bytes at 1–8, zero-padded; signed LE16 count or handle at 9–10; elapsed LE16 KERNAL jiffies at 11–12. Operation numbers are local probe labels: `1` Identify, `2` Open, `3` Write, and `4` Read, rather than Network Target command bytes. Each read/write row describes the last relevant transaction if the transfer was partial.

The host records these fields as `uci_observations`, then closes after a short delay. Peer-close and subsequent explicit local CLOSE/exit behavior are not contained in those five rows. See [hardware testing](hardware-testing.md) and the [C64 probe implementation notes](../c64/README.md).
